# V1 completion

Ship a local-first evaluation framework with a working install → initialize →
run → inspect → CI workflow. This checklist tracks the current Vitest 5 design.

## Decisions

| Area             | Contract                                                                            |
| ---------------- | ----------------------------------------------------------------------------------- |
| Default provider | JSON files under the selected project's `.viteval` directory                        |
| SQLite           | Optional provider using the same dataset/result contracts                           |
| Braintrust       | Official SDK and API contract; deterministic HTTP fixtures verify our adapter       |
| Langfuse         | Optional official client + isolated OpenTelemetry experiment export                 |
| VoltOps          | Optional official SDK for hosted datasets, experiments, and evaluation outcomes     |
| Object storage   | Optional S3/GCS dataset providers with immutable snapshots and conditional catalogs |
| CLI              | maltty for project commands; native Vitest for evaluation arguments and execution   |
| Configuration    | Native `vitest.config.ts`; models initialize in worker setup modules                |
| Result transport | Vitest custom artifacts; persistence consumes the reported results                  |
| Binary           | Compiled command shell; installed Node runtime executes project code                |

EvalPort (#130) is outside the current v1 scope.

Hosted capability limits are explicit: Langfuse and VoltOps dataset rename/delete
and atomic replacement are not exposed by the supported SDK workflows. VoltOps
run history is inspected in its console; the SDK exposes run writes and completion,
and provider-session reads, but not historical run retrieval/listing. See the
[provider guide](../apps/website/guide/providers.md) for the supported operations.

These checks verify the local v1 contract; they do not establish exhaustive code
coverage. Remote CI for the current changes remains separate release evidence.
Existing successful GitHub runs do not verify this uncommitted working tree.
Live model calls are additional account-specific smoke tests. Braintrust's v1
verification relies on its official SDK exercised against local API fixtures:
dataset pagination/replacement, distinct experiment names, result writes,
completion metadata, and result pagination. It does not require live credentials
or testing Braintrust's hosted service.
